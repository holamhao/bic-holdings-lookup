# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

BIC Holdings Lookup: a tiny web app that takes one wallet address (or an uploaded `.csv`/`.xlsx` list of them) and reports its BIC token balance on Arbitrum, its redemption (vesting) contract with the other beneficiary wallet, and active staking per wallet. UI text is English, word for word from the Figma design (including API error messages, staking pool labels, the result `.xlsx` headers and its sheet name); all docs are English too. The root `README.md` is the public GitHub overview (screenshots in `docs/images/`); the data sources and API contract are documented in [`docs/README.md`](docs/README.md), so read that before changing lookup behavior.

## Commands

```bash
npm install
npm run dev     # local server on http://localhost:3000 (PORT env overrides)
npm test        # node --test over test/*.test.js (amounts, batch-file, lookup-history and redemption-progress tests are offline; the rest hit live RPC)
node --test --test-force-exit --test-name-pattern="redemption" test/bic-lookup.test.js   # single test by name
```

Requires Node >= 22. There is no build step, linter, or bundler; the project is ESM (`"type": "module"`) with `viem` as the only dependency.

**Lookup tests are integration tests against live Arbitrum mainnet**, not mocks (`test/amounts.test.js`, `test/batch-file.test.js`, `test/lookup-history.test.js` and `test/redemption-progress.test.js` are the offline exceptions, `batch-file` using the `test/fixtures/addresses.xlsx` fixture written by exceljs). They need network access to the RPC, hard-code real wallet and contract addresses, and assert balances only by shape (decimal string) because values drift. A failing test may mean RPC rate limiting or an outage rather than a code bug. Set `ARBITRUM_RPC_URL` to a keyed provider if the public RPC throttles you.

## Architecture

Request flow: `public/index.html` → `GET /api/lookup?address=0x…` (or `GET /api/lookup-batch?addresses=0x…,0x…`) → `api/*.js` → `lib/bic-lookup.js` → Arbitrum RPC.

- `api/lookup.js` and `api/lookup-batch.js` are the only HTTP surface. They are written against plain Node `req`/`res` (with `sendJson` from `lib/http.js`) so the same files run as Vercel serverless functions (deployed) and under `dev-server.js` (local). Do not introduce framework-specific request or response APIs, or one of the two environments breaks; that is also why the batch endpoint is a GET with no body. `lookup` maps `InvalidAddressError` to 400; `lookup-batch` returns 400 for an empty list or more than `MAX_BATCH_ADDRESSES` (50) and reports invalid addresses per item. Any other failure is 502, and success sets `Cache-Control: s-maxage=15`.
- `lib/bic-lookup.js` holds `lookupWallet` (one wallet, throws on a bad address) and `lookupWallets` (many, invalid inputs become `{ input, error }`). Both run the same three **sequential** viem `multicall` rounds in `lookupHoldings`, because each depends on the previous result: (1) token `symbol`/`decimals` plus the factory's `redeemAddress` of every wallet; (2) for each distinct non-zero vesting contract, its beneficiaries, total, `releasable()` and remaining balance; (3) `balanceOf` plus `getUserDeposits` on every staking pool for every distinct holder (entered wallets and other beneficiaries). `MULTICALL_BATCH_BYTES` is raised from viem's 1 KB default so each round is one `eth_call` instead of many parallel ones. Keep new reads inside these rounds rather than adding individual calls.
- `lib/config.js` is the single place for on-chain addresses (token, vesting factory, staking pools), the RPC URL and `MAX_BATCH_ADDRESSES`. Adding a staking pool is a one-line change here; the lookup loops over `STAKING_POOLS`.
- `lib/abis.js` lists only the read functions the tool uses, written as human-readable ABIs via `parseAbi`. Add a function here before calling it.
- `integrations/google-form/bic-eligibility.gs` is a Google Apps Script (pasted into the form's response Sheet, not run by Node) that consumes `/api/lookup` and applies the eligibility rule. It reads `token.decimals`, `wallets[].balance`, `wallets[].totalStaked` and `redemption.remaining`, so treat those response fields as a public contract. Its Sheet headers (`RESULT_HEADERS`) and status values (`STATUS`) stay Vietnamese because they are data in an existing Sheet: `ensureResultColumns` rejects changed headers and `recheckPending` matches the error status. Setup lives in [`docs/google-form-integration.md`](docs/google-form-integration.md).
- `public/batch-file.js` is a browser ES module, also imported by the Node tests, that reads the first column of an uploaded `.csv`/`.xlsx` (xlsx is unzipped with `DecompressionStream`, no dependency) and builds the result `.xlsx` (minimal zip writer, no dependency). Results are xlsx rather than CSV on purpose: amounts are stored as real numbers so every locale shows its own decimal separator, whereas a comma-decimal Excel misreads a CSV `12.345` as twelve thousand. It owns the upload limits (`MAX_FILE_ROWS` 1000, `MAX_FILE_BYTES` 2 MB) and `BATCH_CHUNK_SIZE`, which must stay ≤ `MAX_BATCH_ADDRESSES`. The page sends chunks sequentially and dedupes addresses first.
- `public/lookup-history.js` is a browser ES module, also imported by the Node tests, with the pure lookup-history logic: newest-first entries (`{ type: 'wallet', address, at }` or `{ type: 'file', fileName, count, at }`), wallets deduped by lowercased address, every file upload kept as its own entry with a repeated name numbered like an OS save (`list (1).csv`, smallest free number, case-insensitive) so file names stay unique, the `HISTORY_LIMIT` of 50, `clearHistoryType` (clears only the wallets or only the files, used by the drawer's per-tab clear), the time formatters (`formatHistoryTime`: "Today at 10:37" / "Yesterday at 16:20" / "Oct 28 at 11:05", plus `formatDateTime` and `formatClock`) and `parseHistory`, which drops malformed stored data. `index.html` owns the `localStorage` reads and writes (wrapped in `try/catch` so the page still works when storage is blocked). History is browser-only by design because there is no database.
- The history UI is a `<dialog>` opened with `showModal()` from the masthead History button: a right drawer on desktop and a bottom sheet at 600px and below, with Wallets/Files tabs, per-row remove, an empty state per tab and an inline "Clear wallets"/"Clear files" confirmation in the footer that clears only the active tab. Clicking a wallet closes the drawer and looks it up again; file rows are not clickable (the browser cannot reopen a local file).
- `public/redemption-progress.js` is a browser ES module, also imported by the Node tests (`test/redemption-progress.test.js`, offline). `redemptionProgress` splits a vesting contract into claimed / claimable / locked as exact decimal strings (BigInt on the scaled strings, no viem in the browser) plus bar percentages that add up to 100. The decimal-string arithmetic it and the page share (`parseUnits`, `formatUnits`, `sumAmounts`) lives in `public/amounts.js`.
- `public/assets/icons/` holds the SVGs exported from Figma, unmodified. `index.html` draws them with CSS `mask-image` on an element whose `background-color` is `currentColor`, so one file follows both themes. To add an icon, export it from Figma into that folder and add one `.icon-<name>` rule; do not redraw or edit the files. `dev-server.js` serves `.svg` as `image/svg+xml` to match Vercel.
- Theme: `<html data-theme="light|dark">` is set by a small inline script in `<head>` before first paint, from `localStorage` key `bic-theme` if present, else `prefers-color-scheme`. The masthead toggle flips it and writes the key (storage access is in `try/catch`). All colors are tokens on `:root` and `:root[data-theme="dark"]`.
- `public/index.html` is a single static page with inline CSS and a module script and no build. Fonts (Newsreader, Be Vietnam Pro, JetBrains Mono) load from one Google Fonts `<link>`. It builds DOM with a small `el()` helper and `textContent` (not `innerHTML`), so keep user- and chain-derived strings out of `innerHTML`.

## Domain details that are easy to get wrong

- All token amounts are returned as decimal **strings** already divided by `decimals` (via `formatUnits`). The API never returns raw `bigint`s, since JSON cannot serialize them.
- "Remaining" for a redemption is the vesting contract's BIC `balanceOf`, not a field on the contract. "Claimable now" is the first element of the `releasable()` tuple.
- A withdrawn staking deposit stays in the `getUserDeposits` array with `withdrawn = true`, so staked totals must filter on `!d.withdrawn`.
- `redeemAddress` returns `0x0` for wallets with no redemption, and the wallets list then contains only the entered wallet. The "Redemption Operator" wallet is just the factory owner (an EOA), not a contract.

## Deployment

Source is public at https://github.com/holamhao/bic-holdings-lookup (MIT); `.github/workflows/test.yml` runs `npm test` on pushes to `main` and on pull requests, so the live-RPC tests run in CI too. Production is https://biclookup.vercel.app (Vercel project `bic-token`, linked in `.vercel/`; deploy with `npx vercel --prod`). Deployed on Vercel Hobby with Framework Preset "Other" and no build settings: `public/` is served statically and each `api/*.js` file becomes a function (`/api/lookup`, `/api/lookup-batch`). `dev-server.js` mirrors this by serving `.html`/`.js`/`.svg`/`.png` files from `public/` (so `public/assets/` works locally too). `public/favicon.svg` and `public/apple-touch-icon.png` (180px, full-bleed) are not Figma exports: they are the Newsreader 600 (opsz 16) "B" glyph outlined to a path, white on `#5F4B8B`, because a favicon SVG cannot load web fonts. `.env*`, `.vercel/` and `.claude/` are gitignored; the only configuration is the optional `ARBITRUM_RPC_URL`. `vercel.json` holds only security headers; its CSP allows scripts/styles from self (inline included, since `index.html` has inline `<script>`/`<style>`), fonts from Google Fonts and `connect-src 'self'`, so any new external resource or API host must be added there or the browser blocks it. `dev-server.js` does not apply these headers. Vercel Web Analytics is the plain-HTML snippet in `index.html`'s `<head>` (`window.va` queue plus `/_vercel/insights/script.js`), not the `@vercel/analytics` npm package, which needs a bundler; the script is same-origin, so the CSP needs no change, and it 404s under `dev-server.js`, which is expected. `.vercelignore` keeps dev-only folders (`plans/`, `docs/`, `test/`, `integrations/`, `.github/`) out of the upload.
